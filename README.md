## 3. Теоретическая база

### 3.1. Задача видеоклассификации

Видеоклассификация — это задача машинного обучения, в которой модель должна определить категорию, тип действия или событие, представленное в видеоролике.

В отличие от классификации изображений, видео содержит не только статическую визуальную информацию, но и изменение сцены во времени. Однако обучение полноценных видеомоделей на сырых видео требует значительных вычислительных ресурсов.

Поэтому в данной работе используется подход предварительного извлечения признаков:

```text
видео → кадры → видеоэмбеддинг → классификатор
````

Дополнительно используется текстовая модальность:

```text
текстовое описание → текстовый эмбеддинг → классификатор
```

Итоговая модель обучается не на сырых видео, а на объединённых признаках:

```text
text embedding + video embedding → категория видео
```

---

### 3.2. Датасет HowTo100M

**HowTo100M** — крупный датасет обучающих видеороликов, содержащий metadata для большого количества видео. Датасет ориентирован на мультимодальное обучение, так как видеоролики связаны с текстовой информацией.

В работе использовались файлы:

```text
HowTo100M_v1.csv
task_ids.csv
```

После объединения таблиц была получена metadata-таблица со следующими полями:

| Поле               | Описание                  |
| ------------------ | ------------------------- |
| `video_id`         | YouTube ID видеоролика    |
| `category_1`       | основная категория        |
| `category_2`       | подкатегория              |
| `rank`             | ранг видео                |
| `task_id`          | идентификатор задачи      |
| `task_description` | текстовое описание задачи |

Пример текстовых описаний:

```text
Freeze Okra
Make Natural Liquid Soap
Make Your Pavers Level
Paint a Rock Using Toothpicks
```

---

### 3.3. Кросс-модальный подход

Кросс-модальный подход предполагает использование нескольких типов данных одновременно. В данной работе используются две модальности:

| Модальность | Источник                | Получаемый признак |
| ----------- | ----------------------- | ------------------ |
| Видео       | кадры из видеофрагмента | video embedding    |
| Текст       | `task_description`      | text embedding     |

Итоговый признак формируется путём объединения текстового и видеоэмбеддинга:

```text
combined embedding = text embedding + video embedding
```

Размерности признаков:

| Признак            | Размерность |
| ------------------ | ----------: |
| Text embedding     |         512 |
| Video embedding    |         512 |
| Combined embedding |        1024 |

---

### 3.4. Модель CLIP

Для извлечения текстовых и визуальных признаков использовалась предобученная модель **CLIP**:

```text
openai/clip-vit-base-patch32
```

CLIP содержит два основных кодировщика:

| Компонент     | Назначение                                 |
| ------------- | ------------------------------------------ |
| Text Encoder  | преобразует текст в вектор признаков       |
| Image Encoder | преобразует изображение в вектор признаков |

В данной работе CLIP не обучался заново. Он использовался как feature extractor, то есть как готовая модель для получения эмбеддингов.

Обучалась только небольшая полносвязная модель-классификатор, которая принимала на вход объединённые текстовые и видеоэмбеддинги.

## 4. Описание разработанной системы

### 4.1. Общая схема работы

Разработанная система работает по следующему алгоритму:

```text
HowTo100M metadata
        ↓
выбор категорий
        ↓
формирование исходной подвыборки
        ↓
загрузка коротких видеофрагментов через yt-dlp
        ↓
извлечение кадров из видео через OpenCV
        ↓
CLIP Image Encoder → video embedding
        ↓
CLIP Text Encoder → text embedding
        ↓
объединение text + video embeddings
        ↓
обучение классификатора
        ↓
оценка качества модели
```

### 4.4. Извлечение кадров

Из каждого видеофрагмента извлекалось 4 кадра с помощью OpenCV.

Схема обработки одного видео:

```text
15-секундный видеофрагмент
        ↓
кадр 1
кадр 2
кадр 3
кадр 4
        ↓
CLIP Image Encoder
        ↓
усреднение эмбеддингов кадров
        ↓
video embedding
```

Для каждого кадра вычислялся CLIP-эмбеддинг размерности 512. Затем эмбеддинги кадров усреднялись:

```text
video embedding = mean(CLIP(frame_1), CLIP(frame_2), CLIP(frame_3), CLIP(frame_4))
```

Таким образом, для каждого видео был получен один визуальный эмбеддинг размерности 512.

В качестве текстовой информации использовалось поле:

Каждое текстовое описание преобразовывалось в текстовый эмбеддинг с помощью CLIP Text Encoder.

Размерность текстового эмбеддинга:

```text
512
```

### 4.6. Объединение признаков

После получения текстового и видеоэмбеддинга они объединялись в один вектор:

```python
X = np.concatenate([text_embeddings, video_embeddings], axis=1)
```

Размерности:

| Признак            | Размерность |
| ------------------ | ----------: |
| Text embedding     |         512 |
| Video embedding    |         512 |
| Combined embedding |        1024 |

Итоговая форма данных:

```text
Text embeddings shape:  (1000, 512)
Video embeddings shape: (1000, 512)
Combined embedding:     (1000, 1024)
```

### 4.8. Архитектура классификатора

Для классификации использовалась полносвязная нейронная сеть `CrossModalClassifier`.

```python
class CrossModalClassifier(nn.Module):
    def __init__(self, input_dim, num_classes):
        super(CrossModalClassifier, self).__init__()

        self.classifier = nn.Sequential(
            nn.Linear(input_dim, 512),
            nn.ReLU(),
            nn.Dropout(p=0.3),

            nn.Linear(512, 128),
            nn.ReLU(),
            nn.Dropout(p=0.2),

            nn.Linear(128, num_classes)
        )

    def forward(self, x):
        return self.classifier(x)
```

Структура модели:

| Слой                | Назначение                                   |
| ------------------- | -------------------------------------------- |
| `Linear(1024, 512)` | обработка объединённого text+video embedding |
| `ReLU`              | нелинейная функция активации                 |
| `Dropout(0.3)`      | снижение переобучения                        |
| `Linear(512, 128)`  | уменьшение размерности признаков             |
| `ReLU`              | нелинейная функция активации                 |
| `Dropout(0.2)`      | дополнительная регуляризация                 |
| `Linear(128, 4)`    | выходной слой на 4 категории                 |
